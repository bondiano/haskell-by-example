# Введение и настройка среды

## Функциональное программирование на практике

Идеи функционального программирования давно проникли в мейнстрим. Вы наверняка пользовались `map`, `filter` и `reduce` в Python, JavaScript или Java. Вы видели, как React строит интерфейсы из чистых функций, а Redux управляет состоянием через редьюсеры. Стримы в Java 8+, LINQ в C#, паттерн-матчинг в Rust — всё это заимствования из мира функциональных языков.

Но в языках общего назначения функциональные техники остаются надстройкой: ничто не мешает обойти их, мутировать состояние или бросить исключение в произвольном месте. Haskell идёт дальше. Он делает функциональный подход *основой* языка, а не опцией:

- **Чистые функции по умолчанию.** Функция `sort :: [Int] -> [Int]` гарантированно не читает файлы, не отправляет HTTP-запросы и не изменяет глобальные переменные. Это следует из её типа.
- **Эффекты явны.** Если функция выполняет ввод-вывод, это отражено в типе: `readFile :: FilePath -> IO String`. Компилятор не позволит случайно смешать чистый код с побочными эффектами.
- **Мощный вывод типов.** Вам редко придётся писать типы вручную — компилятор выводит их сам. При этом типы в Haskell гораздо выразительнее, чем в большинстве промышленных языков.

Результат — код, о котором легко рассуждать, который легко тестировать и рефакторить.

## Почему Haskell

Haskell существует с 1990 года. За это время он из академического эксперимента превратился в язык с развитой экосистемой и реальными промышленными применениями:

- **Финтех.** Standard Chartered использует Haskell для финансового моделирования. Mercury, Klarna, Tsuru Capital строят на нём бэкенды.
- **Компиляторы и инструменты.** GHC сам написан на Haskell. Pandoc — универсальный конвертер документов — один из самых популярных open-source проектов на Haskell. ShellCheck анализирует bash-скрипты.
- **Блокчейн.** Cardano — криптовалютная платформа — написана на Haskell.
- **DevOps и инфраструктура.** Meta (Facebook) использует Haskell для Sigma — системы обнаружения спама, обрабатывающей миллионы запросов в секунду.

Haskell — не самый популярный язык на рынке труда. Но изучение Haskell меняет способ мышления о программировании, и этот эффект переносится на любой другой язык.

## Философия языка

Три кита Haskell:

### Чистота

В Haskell функция — это функция в математическом смысле: при одних и тех же аргументах она всегда возвращает одинаковый результат. Нет скрытых зависимостей от глобального состояния, нет неожиданных побочных эффектов.

```haskell
square :: Int -> Int
square x = x * x
-- square 5 всегда вернёт 25 — не бывает «иногда 25, иногда 26»
```

Побочные эффекты (чтение файлов, сетевые запросы, вывод на экран) не запрещены — они изолированы в типе `IO`. Это делает границу между чистым и эффективным кодом видимой и контролируемой.

### Ленивость

Haskell вычисляет выражения только тогда, когда их результат действительно нужен. Это позволяет работать с бесконечными структурами данных:

```haskell
-- Бесконечный список натуральных чисел
nats :: [Int]
nats = [1..]

-- Берём только первые 5 — вычислятся только они
take 5 nats  -- [1, 2, 3, 4, 5]
```

Ленивость — мощный инструмент абстракции, но требует понимания. Мы подробно разберём её в [главе 9](chapter09.md).

### Строгая система типов

Система типов Haskell — одна из самых выразительных среди языков общего назначения. Она не просто отлавливает ошибки на этапе компиляции, но и служит языком проектирования:

```haskell
-- Тип говорит: функция принимает ключ и ассоциативный список,
-- может вернуть значение, а может не найти ничего
lookup :: Eq a => a -> [(a, b)] -> Maybe b
```

Здесь `Maybe b` кодирует возможность отсутствия результата прямо в типе — не нужен `null`, не нужны исключения для штатных ситуаций. Компилятор заставит вас обработать оба случая.

## О чём эта книга

Эта книга — практическое руководство по Haskell для разработчиков из мейнстрим-языков (JavaScript/TypeScript, Python, Go, Java). Каждая глава строится вокруг **сквозного проекта** — трекера задач (task tracker), который постепенно эволюционирует от простых чистых функций до полноценного REST API с базой данных.

Книга разделена на пять частей:

1. **Основы** (главы 1–6) — типы, функции, ADT, рекурсия, классы типов, стандартные структуры данных.
2. **Эффекты и ошибки** (главы 7–10) — IO, обработка ошибок, ленивость, тестирование.
3. **Абстракции** (главы 11–14) — Functor, Applicative, Monad, трансформеры, JSON.
4. **Реальные приложения** (главы 15–17) — организация проекта, конкурентность, веб-приложение.
5. **Продвинутые темы** (главы 18–21) — DSL, GADTs, линзы, обзор экосистемы.

В приложениях — графика с gloss, FFI (вызов C из Haskell) и обзор компилятора GHC.

**Что вам понадобится:**

- Базовое знание программирования на любом языке.
- Опыт функционального программирования не обязателен, но не помешает.
- Готовность работать в командной строке.

Настоятельно рекомендуем выполнять упражнения — именно в практике закрепляется понимание. Код упражнений доступен в репозитории книги:

## Установка окружения

### GHCup

[GHCup](https://www.haskell.org/ghcup/) — официальный установщик инструментов Haskell. Он управляет версиями компилятора GHC, сборщика Stack и языкового сервера HLS.

```text
$ curl --proto '=https' --tlsv1.2 -sSf https://get-ghcup.haskell.org | sh
```

В процессе установки GHCup предложит установить GHC, Stack и HLS. Соглашайтесь на все компоненты.

```admonish tip title="Знакомый аналог"
GHCup похож на **nvm** (Node.js) или **pyenv** (Python): управляет версиями рантайма и сопутствующих инструментов.
```

После установки проверьте:

```text
$ ghc --version
The Glorious Glasgow Haskell Compilation System, version 9.6.7

$ stack --version
Version 3.7.1 ...
```

### Stack

**Stack** — сборщик проектов на Haskell. Он обеспечивает воспроизводимые сборки: каждый проект привязан к конкретному набору пакетов (resolver), где все библиотеки гарантированно совместимы друг с другом.

```admonish tip title="Знакомый аналог"
Stack похож на **npm** / **yarn** (Node.js) или **cargo** (Rust): управляет зависимостями и сборкой. Resolver в Stack — аналог lock-файла, но на уровне всей экосистемы.
```

### Форматтер и линтер

Хороший код — не только правильный, но и единообразно оформленный. С первого дня мы будем использовать два инструмента:

- **[Fourmolu](https://fourmolu.github.io/)** — автоматический форматтер кода (как Prettier для JavaScript или Black для Python).
- **[HLint](https://github.com/ndmitchell/hlint)** — линтер, который подсказывает идиоматические паттерны (как ESLint для JavaScript).

Установите их через GHCup:

```text
$ ghcup install hlint
$ ghcup install fourmolu
```

Или через cabal:

```text
$ cabal install fourmolu hlint
```

Проверьте установку:

```text
$ fourmolu --version
fourmolu 0.16...

$ hlint --version
HLint v3.8...
```

```admonish note title="Интеграция с редактором"
Если вы используете VS Code с расширением Haskell, HLS автоматически использует fourmolu для форматирования (Shift+Alt+F). Для Neovim добавьте `fourmolu` в конфигурацию `conform.nvim` или `null-ls`.
```

### Редактор

Для работы с Haskell подойдёт любой редактор с поддержкой [HLS (Haskell Language Server)](https://haskell-language-server.readthedocs.io/):

- **VS Code** — расширение [Haskell](https://marketplace.visualstudio.com/items?itemName=haskell.haskell).
- **Neovim** — через `nvim-lspconfig` + `haskell-tools.nvim`.
- **Emacs** — `haskell-mode` + `lsp-mode` или `eglot`.

HLS обеспечивает автодополнение, подсказки типов, переход к определению и автоматический импорт модулей.

```admonish warning title="Важно"
Для корректной работы HLS открывайте в редакторе директорию конкретной главы (например, `exercises/chapter02`), а не корень всего репозитория.
```

### package.yaml

Файл `package.yaml` описывает пакет в формате [hpack](https://github.com/sol/hpack). При сборке hpack автоматически генерирует из него `.cabal`-файл:

```yaml
name: chapter02
version: 0.1.0.0

dependencies:
  - base >= 4.18 && < 5    # стандартная библиотека

library:
  source-dirs: src          # модули библиотеки

tests:
  chapter02-tests:
    main: Spec.hs
    source-dirs: test
    dependencies:
      - chapter02            # зависимость от самой библиотеки
      - hspec                # тестовый фреймворк
```

### stack.yaml

В корне репозитория лежит `stack.yaml` — конфигурация Stack для всего проекта:

```yaml
resolver: lts-22.44       # набор пакетов (включает GHC 9.6.7)

packages:
  - exercises/chapter02    # список пакетов проекта
```

**Resolver** — это снапшот Stackage: фиксированный набор версий пакетов, проверенных на совместимость. Когда в `package.yaml` вы указываете зависимость `hspec`, Stack берёт ту версию, которая входит в снапшот `lts-22.44`.

### Модули

Каждый файл `.hs` содержит один модуль. Имя модуля должно совпадать с путём к файлу:

```haskell
-- Файл: src/Euler.hs
module Euler where

answer :: Int -> Int
answer limit = sum [x | x <- [1 .. limit - 1], x `mod` 3 == 0 || x `mod` 5 == 0]
```

Модуль `Euler` экспортирует функцию `answer`. Другие модули могут импортировать её:

```haskell
import Euler (answer)
```

| Команда | Действие |
|---------|----------|

## Тестирование с hspec

В этой книге мы используем [hspec](https://hspec.github.io/) — тестовый фреймворк для Haskell. Посмотрим на тесты в `test/Spec.hs`:

```haskell
module Main where

import Test.Hspec
import Euler (answer)
import MySolutions (diagonal, circleArea, collatzLength)

main :: IO ()
main = hspec $ do
  describe "Euler — сумма кратных" $ do
    it "ниже 10 равна 23" $
      answer 10 `shouldBe` 23

    it "ниже 1000 равна 233168" $
      answer 1000 `shouldBe` 233168

  describe "diagonal" $ do
    it "диагональ 3×4 равна 5" $
      diagonal 3 4 `shouldBe` 5.0
  ...
```

Структура проста:

- `describe` — группирует связанные тесты.
- `it` — один тест с описанием на естественном языке.
- `shouldBe` — проверяет равенство результата и ожидаемого значения.

```admonish tip title="Знакомый аналог"
hspec похож на **Jest** (JavaScript) или **pytest** (Python). `describe` → `describe`/`class`, `it` → `test`/`def test_`, `shouldBe` → `expect().toBe()`/`assert`.
```

Запустите тесты:

```text
$ cd exercises/chapter02
$ stack test
```

Тесты для `answer` пройдут, а остальные упадут с ошибкой `Prelude.undefined` — это ожидаемо, потому что функции в `MySolutions.hs` ещё не реализованы:

```text
Euler — сумма кратных
  ниже 10 равна 23 [✔]
  ниже 1000 равна 233168 [✔]
diagonal
  диагональ 3×4 равна 5 [✘]
```

## Решаем вместе: задача Эйлера №1

Прежде чем переходить к упражнениям, разберём пример из `src/Euler.hs`.

**Задача Эйлера №1:** найти сумму всех натуральных чисел ниже 1000, которые кратны 3 или 5.

```haskell
answer :: Int -> Int
answer limit = sum [x | x <- [1 .. limit - 1], x `mod` 3 == 0 || x `mod` 5 == 0]
```

Разберём по частям:

1. **`answer :: Int -> Int`** — сигнатура типа. Функция принимает `Int` и возвращает `Int`. Сигнатуры необязательны (компилятор выведет тип сам), но мы рекомендуем писать их всегда — они служат документацией и помогают при отладке.

2. **`[x | x <- [1 .. limit - 1], ...]`** — генератор списка (list comprehension). Читается: «список всех `x`, где `x` берётся из диапазона от 1 до `limit - 1`...»

3. **`` x `mod` 3 == 0 || x `mod` 5 == 0 ``** — ...и `x` делится на 3 или на 5. Обратные кавычки превращают функцию в инфиксный оператор: `mod x 3` и `` x `mod` 3 `` — одно и то же.

4. **`sum`** — складывает все элементы списка.

Проверим в GHCi:

```text
> answer 10
23

> [x | x <- [1..9], x `mod` 3 == 0 || x `mod` 5 == 0]
[3,5,6,9]

> sum [3,5,6,9]
23
```

### Практика ★☆☆

1. Реализуйте функцию `diagonal`, которая вычисляет длину диагонали (гипотенузу) прямоугольного треугольника по двум катетам. Используйте теорему Пифагора и функцию `sqrt`.

    ```haskell
    diagonal :: Double -> Double -> Double
    ```

    ```text
    > diagonal 3 4
    5.0
    ```

2. Реализуйте функцию `circleArea`, которая вычисляет площадь круга по радиусу. Используйте константу `pi` (доступна из `Prelude`).

    ```haskell
    circleArea :: Double -> Double
    ```

    ```text
    > circleArea 10
    314.1592653589793
    ```

### Практика ★★☆

3. Реализуйте функцию `collatzLength`, которая возвращает количество шагов в [последовательности Коллатца](https://ru.wikipedia.org/wiki/Гипотеза_Коллатца) до достижения 1.

    Правила:
    - Если число чётное — делим на 2.
    - Если нечётное — умножаем на 3 и прибавляем 1.
    - Повторяем, пока не получим 1.

    Например, для числа 6: 6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1 — **8 шагов**.

    ```haskell
    collatzLength :: Int -> Int
    ```

    *Подсказка:* используйте рекурсию и guards (охранные выражения). Функция `even :: Int -> Bool` проверяет чётность. Guards — конструкция, которую мы подробно разберём в [главе 3](chapter03.md), но вот пример:

    ```haskell
    absolute :: Int -> Int
    absolute n
      | n < 0     = -n
      | otherwise = n
    ```
